# IaC Template — Scaffold Generator

When invoked, generate the minimal project structure for a client project consuming `@iac-template/core`. Read `plan.md` first to determine the scenario and the constructs to activate.

---

## Directory Structure

### E1 / E2

```
infra/
├── app.ts                    # CDK app entry point — sole composition root
├── cdk.json                  # CDK configuration
├── package.json              # @iac-template/core + aws-cdk-lib as dependencies
├── tsconfig.json             # TypeScript strict mode
└── functions/
    └── [domain]/             # One directory per functional domain (from plan.md)
        ├── resource.ts       # Lambda definition (name, runtime, IAM permissions)
        └── handler.ts        # Lambda handler
```

### E3

```
infra/
├── generate.ts               # E3Generator entry point
├── package.json              # @iac-template/core only (no aws-cdk-lib needed at runtime)
├── tsconfig.json             # TypeScript strict mode
└── docker/
    └── docker-compose.yml    # Generated by E3Generator.generate()
```

## File Templates

### `infra/package.json`

```json
{
  "name": "[project-name]-infra",
  "version": "0.1.0",
  "private": true,
  "scripts": {
    "build": "tsc",
    "synth": "cdk synth",
    "deploy": "cdk deploy",
    "diff": "cdk diff",
    "generate": "ts-node generate.ts"
  },
  "dependencies": {
    "@iac-template/core": "^1.0.0",
    "aws-cdk-lib": "^2.0.0",
    "constructs": "^10.0.0"
  },
  "devDependencies": {
    "aws-cdk": "^2.0.0",
    "typescript": "^5.0.0",
    "ts-node": "^10.0.0",
    "@types/node": "^20.0.0"
  }
}
```

For E3, remove `aws-cdk-lib`, `constructs`, `aws-cdk`, and the `synth`/`deploy`/`diff` scripts. Keep `generate`.

### `infra/cdk.json` (E1/E2 only)

```json
{
  "app": "npx ts-node app.ts",
  "context": {
    "@aws-cdk/aws-lambda:recognizeLayerVersion": true,
    "@aws-cdk/core:stackRelativeExports": true
  }
}
```

### `infra/app.ts` (E1/E2)

Generate this file using the composition code from `plan.md` Step 3. The file must:
- Import only the constructs listed in `plan.md`
- Set `OperationMode` to the scenario identified in `spec.md`
- Pass all parameters explicitly — no hardcoded secrets or ARNs
- Use `process.env.CDK_ACCOUNT` and `process.env.CDK_REGION` for the environment

### `infra/functions/[domain]/resource.ts`

One file per functional domain listed in `plan.md`:

```typescript
import { defineFunction } from '@iac-template/core';

export const [domain]Function = defineFunction({
  name: '[domain]',
  runtime: 'nodejs20.x',
  entry: './functions/[domain]/handler.ts',
});
```

### `infra/functions/[domain]/handler.ts`

```typescript
import { APIGatewayProxyHandler } from 'aws-lambda';

export const handler: APIGatewayProxyHandler = async (event) => {
  return {
    statusCode: 200,
    body: JSON.stringify({ message: '[domain] handler placeholder' }),
  };
};
```

### `infra/generate.ts` (E3 only)

```typescript
import { E3Generator } from '@iac-template/core';

E3Generator.generate({
  runtimeVersion: '[runtime from plan.md]',
  allowedLibraries: [/* libraries from plan.md */],
  outputDir: './docker',
});
```

## After Scaffold Generation

1. Run `npm install` inside `infra/`.
2. For E1/E2: run `npm run synth` to verify the CDK app synthesizes without errors.
3. For E3: run `npm run generate` to verify `docker/docker-compose.yml` is created.
4. Commit the scaffold as the initial project commit before any business logic is added.
